## 1. 背景与目标

HarmonyOS 从 **API 22** 起提供 **OHAudioSuite（音频编创）** 的 C/C++ 接口，提供引擎/管线/节点式的
**专业级音频效果处理**（降噪、均衡、音源分离、混音、变声、空间渲染等）。

本 Demo 目标：
1. 用 **离线编辑（EDIT_MODE）** 跑通一条贴近业务的管线；
2. 场景：**输入一段清唱/混音音频 → 降噪 → 音源分离（人声/伴奏）→ 混音 → 输出**；
3. 交付：可运行 Demo（基于官方样例）+ 定制参考实现 + 技术方案 + 演示 PPT。

> 说明：OHAudioSuite **只处理裸 PCM**；音频文件的解码（mp3/aac/wav→PCM）与编码（PCM→wav）需业务侧自备。

---

## 2. 核心架构（引擎 / 管线 / 节点）

```
OH_AudioSuiteEngine（最多 10 条管线）
  └─ OH_AudioSuitePipeline（EDIT_MODE 离线 | REALTIME_MODE 实时）
       └─ Node： 输入节点 → 效果节点* → 输出节点
```

- **反向驱动**：调用 `OH_AudioSuiteEngine_RenderFrame()`（单输出）/ `MultiRenderFrame()`（多输出）后，
  输出节点**逐级向上游请求数据**，最终触发输入节点的 `RequestDataCallback`，由业务把 PCM 填进去。
- **节点类型**：输入 `INPUT_NODE_TYPE_DEFAULT`、输出 `OUTPUT_NODE_TYPE_DEFAULT`、效果节点（见 §4）。
- **状态机**：`stopped`（初始/StopPipeline 后，释放缓存）↔ `running`（StartPipeline 后，做完整性检查）。
  只有 **stopped** 状态下才能连接/断开/移除节点。
- **连接规则**：单向 `输入 → 效果* → 输出`；每条管线**恰好 1 个输出节点**；混音节点支持多路输入；
  **音源分离节点是多输出，后面只能接输出节点**（因此"分离"和"混音"要拆两趟）。

## 3. 离线编辑标准流程（Demo 主干）

1. `OH_AudioSuiteEngine_Create(&engine)`
2. `OH_AudioSuiteEngine_CreatePipeline(engine, &pipe, AUDIOSUITE_PIPELINE_EDIT_MODE)`
3. 建输入节点：`NodeBuilder_Create` → `SetNodeType(INPUT)` → `SetFormat(...)` → `SetRequestDataCallback(...)` → `CreateNode`
4. `NodeBuilder_Reset` → 建效果节点（如降噪/均衡）→ 调 `SetXxx()` 设参数
5. `NodeBuilder_Reset` → 建输出节点：`SetNodeType(OUTPUT)` + `SetFormat(...)` → `CreateNode`
6. `ConnectNodes(input → effect → output)`
7. `StartPipeline` → 循环 `RenderFrame(pipe, buf, frameSize, &resp, &finished)` 取处理后的 PCM
8. `StopPipeline` → 依次 `DestroyNode / DestroyPipeline / Destroy`

**帧大小**：`frameSize = 帧时长(ms) × 采样率 × 声道数 × 每样本字节 / 1000`
（示例统一 20ms；**采样率 11025 时用 40ms**）。

## 4. 效果节点能力（12 种）

| 效果 | 节点枚举 | 关键参数/API |
|---|---|---|
| 均衡器 | `EFFECT_NODE_TYPE_EQUALIZER` | 10 段(31~16kHz)，增益[-10,10]dB，`SetEqualizerFrequencyBandGains`；预置民谣/中国风/古典/舞曲/爵士/流行/R&B/摇滚 |
| 降噪 | `EFFECT_NODE_TYPE_NOISE_REDUCTION` | 无参数，接入即生效；`BypassEffectNode` 可旁路 |
| 声场 | `EFFECT_NODE_TYPE_SOUND_FIELD` | 前置/宏大/近场/宽广，`SetSoundFieldType` |
| 音源分离 | `EFFECT_MULTII_OUTPUT_NODE_TYPE_AUDIO_SEPARATION` | 输出[0]人声 + [1]伴奏；**依赖 NPU**，用前先 `IsNodeTypeSupported`；`MultiRenderFrame` |
| 声音美化 | `EFFECT_NODE_TYPE_VOICE_BEAUTIFIER` | 清澈/剧场/CD/录音棚 |
| 环境效果 | `EFFECT_NODE_TYPE_ENVIRONMENT_EFFECT` | 广播/听筒/水下/留声机 |
| 混音 | `EFFECT_NODE_TYPE_AUDIO_MIXER` | 多路 → 一路（≤3 个） |
| 空间渲染 | `EFFECT_NODE_TYPE_SPACE_RENDER` | 固定/旋转/扩展三模式 |
| 传统变声 | `EFFECT_NODE_TYPE_PURE_VOICE_CHANGE` | 性别 + 7 种类型 + pitch[0.3,3.0] |
| 通用变声 | `EFFECT_NODE_TYPE_GENERAL_VOICE_CHANGE` | 10 种风格 |
| 变速变调 | `EFFECT_NODE_TYPE_TEMPO_PITCH` | speed[0.5,10]、pitch[0.1,5] |
| HOA 空间音频 | `EFFECT_NODE_TYPE_HOA_SPACE_RENDER` | HOA(1~3 阶)→双耳，前置必须是 HOA 输入 |

## 5. Demo 设计

### 5.1 三条管线（可选演示）

**A. 最简：降噪 + 均衡（单管线、最稳）**
```
input(PCM) → NOISE_REDUCTION → EQUALIZER(流行) → output
```
参照 `demo/offline_pipeline_reference.cpp::RunDenoiseEq()`。

**B. 音源分离（第一趟）**
```
input(PCM) → AUDIO_SEPARATION → output(multi: 人声 / 伴奏)
```
写 `vocals.pcm`、`accomp.pcm`；参照 `RunSeparation()`。

**C. 降噪 + 均衡 + 混音（第二趟）**
```
input(vocals)  → DENOISE   --\
                               >→ MIXER → output
input(accomp)  → EQUALIZER --/
```
写 `mixed.pcm`；参照 `RunMix()`。

> 完整"清唱伴奏"链路 = **B → C**（分离后，人声降噪、伴奏均衡，再混音）。
> 因为分离节点只能接输出，所以必须拆成两趟，不能一条管线里"分离→混音"。

### 5.2 与官方样例的关系
- `demo/AudioSuiteSample/`：官方可运行样例（DevEco 工程，含 NAPI `audio_suite.cpp`、离线
  `manual_rendering.cpp`、效果策略 `audio_effect/`、实时 `real_time_rendering.cpp`、空间渲染、
  格式转换、ArkTS UI `Index.ets`）。**直接作为运行 Demo 基线。**
- `demo/offline_pipeline_reference.cpp`：本方案的**定制离线管线**参考实现（上述 A/B/C 三条）。

### 5.3 数据流
```
音频文件 --解码--> PCM(S16LE/48k/ST) --输入节点回调--> 管线(效果) --> PCM --> 编码/存 wav
```
Demo 里用 `PcmBuffer{buffer,size,written}` + `OnRequestData()` 回调把 PCM 喂给管线，
`RenderFrame` 拿到的就是处理后的 PCM，直接 `fwrite` 落盘（wav 头可自行补）。

## 6. 构建与运行

### 6.1 环境
- DevEco Studio（HarmonyOS SDK **API 22+**；空间渲染需 23+，HOA 需 26+）
- 真机或模拟器（**音源分离依赖 NPU，模拟器/部分机型可能不支持**）

### 6.2 链接与头文件
```cmake
target_link_libraries(entry PUBLIC libohaudiosuite.so)
# 实时/空间渲染播放还需：
target_link_libraries(entry PUBLIC libohaudio.so)
```
```cpp
#include <ohaudiosuite/native_audio_suite_base.h>
#include <ohaudiosuite/native_audio_suite_engine.h>
```

### 6.3 运行官方样例
1. DevEco 打开 `demo/AudioSuiteSample/`；
2. 配置签名（自动签名），选择 API 22+ 设备；
3. 运行 → 按 README 各按钮体验：播放/加效果/音源分离/混音/实时预览/空间渲染/格式转换。

### 6.4 集成定制管线
把 `offline_pipeline_reference.cpp` 加入 `entry/src/main/cpp/`，在 `CMakeLists.txt` 的
`add_library(entry SHARED ...)` 里加该源文件，并在 `Index.d.ts`/NAPI 注册对应方法即可。

## 7. 约束与注意事项

1. **音源分离**：多输出、依赖 NPU、后面只能接输出；每管线≤1 个。用前 `IsNodeTypeSupported`。
2. **混音节点**：≤3 个/管线，支持多路输入。
3. **数量上限**：输出=1/管线；输入 5(旧)/15(新)；其余效果每类 5(旧)/15(新)；引擎≤10 管线。
4. **实时预览**：效果节点**不能动态增删**，只能改参数；`RenderFrame` 耗时随节点数增加，注意卡顿。
5. **格式**：只有输入/输出节点能设格式；中间效果节点不改格式。
6. **只有 PCM**：解码/编码自备；帧大小公式里 11025Hz 用 40ms。
7. **生命周期**：`StopPipeline` 后节点释放缓存；`StartPipeline` 才做完整性校验，连接错误在此报。

## 8. 风险与后续

- **设备兼容**：音源分离依赖 NPU，需在目标机型实测支持矩阵。
- **时长/延迟**：离线模式整段处理、时延不重要；实时预览需盯节点数与帧耗时。
- **质量**：官方效果节点为通用实现，若追求"专业级去噪/分离"，可评估叠加上层算法或后续版本能力。
- **扩展方向**：空间渲染（3D 定位/环绕）、HOA、变声/变速变调可用于互动玩法。
